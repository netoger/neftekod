# Нефтекод-2026 — мультиагентный советчик оператору

Система получает состояние технологической цепочки **АВТ → гидроочистка (24-2000) →
блендинг**, прогнозирует качество дизельного топлива, оценивает риск и предлагает
оператору безопасное изменение режима — либо мотивированно отказывается советовать.

Жёсткое ограничение, которое нельзя нарушить ничем: **сера в товарном ДТ ≤ 10 мг/кг**.

План работ и разбор данных — в [`PLAN.md`](PLAN.md).

---

## Быстрый старт

```bash
python -m venv .venv
.venv\Scripts\activate           # Linux/macOS: source .venv/bin/activate
pip install -r requirements.txt
pip install -e .
```

Укажи, где лежит выданный пакет данных (каталог с `avt_tags.csv`, `ЛИМСы….xlsx` и т.д.).
По умолчанию ожидается `../hackaton_neftekod_2026`; переопределяется в
`config/paths.yaml` или переменной окружения:

```bash
set NEFTEKOD_DATA=C:\путь\к\пакету     # Linux/macOS: export NEFTEKOD_DATA=...
```

Дальше по шагам:

```bash
python scripts/prepare_data.py       # сырьё -> parquet-кэш (один раз, ~1-2 мин)
python scripts/build_tag_config.py   # аудит тегов -> config/tags.yaml + reports/
```

## Допущения (обязательный раздел по ТЗ)

Всё, что здесь перечислено, — решения команды, а не паспортные данные установки.

1. **Модельные диапазоны параметров.** Промышленных пределов в пакете нет.
   За рабочий диапазон каждого тега принят интервал `p05..p95` его истории
   (`model_range` в `config/tags.yaml`). Это ДОПУЩЕНИЕ для эксперимента,
   а не разрешённый предел оборудования.
2. **Лимиты скорости изменения режима.** Заданы в `config/constraints.yaml`
   как доля модельного диапазона за цикл; для температур реактора — не более
   2 °C за шаг. Основано на общей практике, не на регламенте установки.
3. **Значение `307.0` — маркер залипшего датчика.** В выгрузке нет ни одного NaN,
   но значение ровно `307.0` встречается в физически несовместимых тегах
   (плотность нефти, расходы, температуры) и без разброса. Считаем его
   отсутствием данных.
4. **Потолок `20.0` у поточного анализатора серы** — предел шкалы прибора.
   Такие точки считаем цензурированными сверху и не учим на них модель как
   на точных значениях.
5. **Букве в имени тега не верим.** Смысл берём из листа КИП, но и его
   сверяем с фактическим диапазоном: часть описаний в справочнике не сходится
   с физикой сигнала (см. `reports/tag_audit.csv`). Спорные теги помечены
   `trust: no` и в модель не берутся без отдельного разбора.
6. **Спецификация, кроме серы**, в пакете не задана. Остальные показатели
   качества сверяем с ЕН 590 / ГОСТ 32511 и помечаем это как допущение.
7. **Проверка ограничения по сере ведётся по p90 прогноза**, а не по медиане:
   вариант, проходящий «в среднем», но валящийся на верхней границе
   неопределённости, считается недопустимым.

## Правила работы с данными (чтобы не потерять баллы)

* **Никакого случайного train/test split.** Разбиение только по времени,
  границы — в `config/constraints.yaml`, между кусками зазор (embargo).
* **ЛИМС и ПАК присоединяются только «последним известным на момент t»**
  (`merge_asof`, direction=backward), и рядом обязательно кладётся **возраст**
  замера. Сопоставление по номеру строки запрещено — у источников разная частота.
* **Признаки — только из прошлого**: лаги и скользящие агрегаты. Изменение
  режима сказывается на качестве не сразу, поэтому целевая переменная берётся
  со сдвигом вперёд, а признаки — назад.
